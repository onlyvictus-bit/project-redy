## RED Bugs Found and Fixed

### 1. Bootstrap error swallowed (App.tsx)
**Problem:** If `bootstrap()` fails, `state.error` is set by `runAction`, but `!snapshot` returns the loading screen. Error banner is inside the post-snapshot layout — user sees "Booting Triad Workbench..." forever with no error message.

**Fix:** `src/renderer/src/App.tsx`
```tsx
if (!snapshot) {
  return (
    <div className="loading-screen">
      {error ? <p className="error-banner">{error}</p> : <p>Booting Triad Workbench...</p>}
    </div>
  );
}
```

---

### 2. resizeTerminal channel dead (TerminalPane.tsx)
**Problem:** `resizeTerminal` was declared in ipc.ts, wired in preload, and registered in ipcMain — but no renderer component ever called it. The backend PTY stayed at its default column width forever, causing wrong line wrapping and cursor positioning in interactive sessions.

**Fix:** `src/renderer/src/components/TerminalPane.tsx` — added ResizeObserver:
```tsx
useEffect(() => {
  if (!containerRef.current || !sessionId) return;
  const observer = new ResizeObserver(() => {
    if (fitAddonRef.current && terminalRef.current) {
      fitAddonRef.current.fit();
      const { cols, rows } = terminalRef.current;
      void window.workbench.resizeTerminal(sessionId, cols, rows).catch(() => undefined);
    }
  });
  observer.observe(containerRef.current);
  return () => observer.disconnect();
}, [sessionId]);
```

---

### 3. Ollama model dropdown not synced to backend (App.tsx)
**Problem:** The Ollama model `<select>` and `<input>` in the right rail only updated local React state (`ollamaModel`). The backend only received the model when a personality button was clicked in AgentPanel. If the user changed the model dropdown and immediately ran "away-monitor" without clicking a personality button, the workflow used the stale backend model.

**Fix:** `src/renderer/src/App.tsx` — onChange now calls `setOllamaRole` immediately:
```tsx
onChange={(event) => {
  const model = event.target.value;
  setOllamaModel(model);
  void setOllamaRole(snapshot.agents.ollama.role, model);
}}
```

## Duplicate Promote Buttons — Non-Conflicting (Confirmed)

Both `TaskCard` and `TaskDetailPanel` render promote buttons when `task.stage === 'promote'`. Both are shown simultaneously when a task is selected. They are **not** a double-fire risk because:
- They are independent DOM elements — clicking one doesn't affect the other
- TaskCard's promote buttons have `e.stopPropagation()` to prevent card-click from firing
- Both call the same `promoteTask` store action — first click promotes and the snapshot update removes both sets of buttons
